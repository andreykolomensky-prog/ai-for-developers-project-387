# Записи хранятся в памяти процесса

Типы встреч и записи хранятся в памяти одного процесса Node.js, без базы данных: контейнер по условию проверки стартует без внешних зависимостей, а сохранность после перезапуска в приёмку не входит. Перезапуск приложения сбрасывает данные, при старте сервер заново создаёт два типа встреч.

На этом же решении держится защита от двойной записи. Проверка занятости и добавление записи выполняются синхронно в одном обработчике, а Node.js исполняет код в одном потоке, поэтому между проверкой и добавлением не может вклиниться другой запрос: из одновременных запросов на пересекающееся время успешным будет ровно один.

## Consequences

- Приложение нельзя запускать в нескольких экземплярах: у каждого будет своё состояние, и правило занятости перестанет выполняться.
- При переходе на базу данных проверку пересечения нужно будет перенести в транзакцию или ограничение базы.
