# AGENTS.md

Сервис записи на звонок: владелец публикует время, гость бронирует свободный слот. Сценарий и ограничения описаны в [README.md](README.md).

## Команды

Версии инструментов записаны в `mise.toml`, все команды запускаются через mise.

- `mise install` ставит Node.js и hk, подключает git-хуки.
- `mise run dev` запускает бекенд на `:3000` и фронтенд (Vite) на `:5173`.
- `mise run check` запускает все проверки: линтер, типы, актуальность сгенерированных файлов, API-тесты, тесты интерфейса и браузерный сценарий. Эту же команду вызывает CI.
- `mise run lint`, `mise run typecheck`, `mise run test`, `mise run e2e` запускают проверки по отдельности.
- `mise run generate` пересобирает OpenAPI, клиентский SDK и серверные типы из `api/main.tsp`.
- `mise run format` исправляет форматирование и автоисправимые замечания линтера.
- `mise run start` собирает фронтенд и запускает приложение на `PORT` (по умолчанию 3000).
- Один тест: `mise exec -- vitest run test/bookings.test.ts`, один браузерный сценарий: `mise exec -- playwright test -g "название"`.

## Устройство проекта

- `api/main.tsp` контракт API в TypeSpec, единственный источник правды об API.
- `server/` бекенд на Fastify: `app.ts` собирает приложение, `main.ts` запускает его на `PORT`. Маршруты и проверка запросов строятся из OpenAPI, обработчики операций лежат в `handlers.ts`, правила расписания и записи в `schedule.ts` и `booking.ts`, данные в памяти в `store.ts`.
- `web/` фронтенд на React, Vite и Mantine. Собирается в `dist/web`, в продакшене его раздаёт сервер.
- `test/` API-тесты на Vitest: ходят в запущенный сервер по HTTP и сверяют каждый ответ с контрактом. Тесты интерфейса лежат рядом с компонентами в `web/src/**/*.test.tsx` и работают в jsdom.
- `e2e/` браузерные сценарии на Playwright: работают с собранным приложением и настоящим сервером, ответы API не подменяются.
- API находится под префиксом `/api`, остальные пути отдают фронтенд.
- Словарь проекта в `GLOSSARY.md`, принятые решения в `docs/adr/`.

## Правила

- Сгенерированные каталоги `api/generated/`, `web/src/api/generated/` и `server/generated/` руками не правятся. Порядок изменения API: правка `api/main.tsp`, затем `mise run generate`, затем код сервера и фронтенда. Результат генерации коммитится, CI проверяет его актуальность.
- Фронтенд обращается к API только через сгенерированный SDK, прямой вызов `fetch` запрещён линтером.
- Правила бронирования проверяет сервер. Интерфейс только показывает занятость и сообщения сервера.
- Сервер запускается без сборки: Node.js исполняет TypeScript напрямую. Поэтому импорты пишутся с расширением `.ts`, а `enum`, `namespace` и свойства-параметры конструктора не используются.
- Перед коммитом `mise run check` должен быть зелёным.
- Коммиты идут по [Conventional Commits](https://www.conventionalcommits.org): `feat: ...`, `fix: ...`, `docs: ...`, `test: ...`, `refactor: ...`, `chore: ...`, `ci: ...`. Формат проверяет хук `commit-msg`.
- Коммит реализации ссылается на тикет, который он закрывает: `feat: запись на свободный слот (#12)`.
- Файл `.github/workflows/hexlet-check.yml` принадлежит Хекслету: его нельзя менять, переименовывать и удалять.

## Работа в GitHub Actions

Агент OpenCode запускается на раннере по команде `/oc` в комментарии и по событиям репозитория. Воркфлоу описаны в [README.md](README.md).

- На раннере некому ответить на вопрос в терминале. Вопросы и результаты пишутся комментарием в issue или pull request, из которого пришла команда.
- Скиллы лежат в `.claude/skills/`, настройки трекера в `docs/agents/`. Спецификации и тикеты публикуются командой `gh`, токен уже лежит в `GH_TOKEN`.
- Файлы вне репозитория не читаются и не изменяются, это запрещено в `opencode.json`.
- Перед завершением правки кода `mise run check` должен быть зелёным. Результат команды приводится в ответе.

## Agent skills

Проект ведётся набором скиллов [mattpocock/skills](https://github.com/mattpocock/skills): `/grill-with-docs`, `/wayfinder`, `/to-spec`, `/to-tickets`, `/implement`, `/implement-spec`. Скиллы установлены в `.claude/skills/`, версии зафиксированы в `skills-lock.json`. Их файлы руками не правятся, обновление: `npx skills@latest add mattpocock/skills`.

### Issue tracker

Задачи, карта решений, спецификация и тикеты живут в GitHub Issues этого репозитория, работа идёт через `gh`. See `docs/agents/issue-tracker.md`.

### Triage labels

Используются пять меток по умолчанию: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: один `GLOSSARY.md` и `docs/adr/` в корне репозитория. See `docs/agents/domain.md`.
